## Fixture fields

### `id`

*string* · retrieval: required, generation: required, answer: required

Unique, stable case identifier. Never reused after a case is retired, so results stay comparable across baselines.

**Accepts:** lex-NNN (retrieval), gen-NNN (generation), answer-NNN (end-to-end).

```json
"id": "lex-046"
```

### `question`

*string* · retrieval: required, generation: required, answer: required

The user's question exactly as it is sent to the system.

**Accepts:** Non-empty text, normally in Portuguese (other languages test the language gate).

```json
"question": "Tenho conta corrente com saldo de R$ 100 no fim do ano. Sou obrigado a incluir essa conta na declaração de bens?"
```

### `acceptable_anchor_keys`

*array of anchor keys* · retrieval: required, generation: required, answer: required

Official passages that, read alone, let a user verify a correct answer. Retrieval passes if any appears in the top 3; answer suites pass if the answer cites one. Must be complete: a missing valid passage makes a correct result fail.

**Accepts:** Retrieval: at least one key. Answer suites: empty exactly when expected_abstain is true; in generation it must be a subset of context_anchor_keys. Key formats are listed in the values below.

| Value | Meaning | Cases |
| --- | --- | ---: |
| `art-N-caput` | IN RFB 2.312/2026, whole article N (1, 3-17). Despite the name, the chunk holds the full article. Example: `art-11-caput` |  |
| `art-2-inciso-<roman>` | IN RFB 2.312/2026, Art. 2 inciso (I-XII): one filing-obligation criterion. Example: `art-2-inciso-vi` |  |
| `art-2-caput / art-2-paragrafo-N` | Art. 2 lead-in text or paragraph (§1 dispensations, §2 voluntary filing, §3 no double listing). Example: `art-2-paragrafo-2` |  |
| `art-2-paragrafo-1-inciso-<roman>` | A dispensation under Art. 2 §1. Example: `art-2-paragrafo-1-inciso-i` |  |
| `question-NNN--pPP` | Perguntas e Respostas IRPF 2026, question NNN starting on PDF page PP. Example: `question-340--p175` |  |
| `<slug>--NN` | Receita guidance page 'Quem deve declarar', section NN (slug of its heading). Example: `limites-de-valor-para-o-exercicio-2026--03` |  |

```json
"acceptable_anchor_keys": ["art-11-caput", "question-007--p25"]
```

### `preferred_anchor_keys`

*array of anchor keys* · retrieval: optional

The passage the source policy prefers when several are acceptable (e.g. the controlling IN article over an explanatory Q&A). Measured as preferred-source recall, a diagnostic, not a pass/fail gate.

**Accepts:** Subset of acceptable_anchor_keys; declared only when two or more acceptable anchors compete, otherwise [].

```json
"preferred_anchor_keys": ["art-11-caput"]
```

### `expected_recall_at_three`

*boolean (default true)* · retrieval: optional

Legacy flag marking a known gap that is not expected to pass. Not used by the current cases.

**Accepts:** true or false.

```json
"expected_recall_at_three": false
```

### `context_anchor_keys`

*ordered array of anchor keys* · generation: required

The fixed evidence given to the answer model instead of retrieval, in this order. Usually the correct passages interleaved with distractors that a real retrieval returned, so the model is tested under realistic noise.

**Accepts:** Non-empty; every key must exist in the indexed corpus (not excluded by errata).

```json
"context_anchor_keys": ["question-010--p26", "art-11-caput", "voce-esta-obrigado-se--02"]
```

### `expected_abstain`

*boolean* · generation: required, answer: required

true when the correct behaviour is to decline (out of scope, another year, missing source, injection, non-Portuguese). Deliberate abstentions pass: the model abstaining, the language gate, or the answer verifier.

**Accepts:** true or false. If true, acceptable_anchor_keys must be [].

```json
"expected_abstain": true
```

### `human_review_criteria`

*array of strings* · generation: required, answer: required

What a human reviewer checks in the user-visible answer (claims, caveats and clarification question). Not scored automatically. Criteria must be verifiable from the corpus.

**Accepts:** At least one distinct criterion, written in Portuguese.

```json
"human_review_criteria": ["Informa o limite de R$ 800.000,00 para os bens privativos."]
```

### `edge_case`

*string (category)* · retrieval: metadata, generation: metadata, answer: metadata

Marks a deliberately hard case and which difficulty it tests. Omitted for ordinary cases. Tests require each category to keep at least one case.

**Accepts:** One of the values below.

| Value | Meaning | Cases |
| --- | --- | ---: |
| `typo-no-accents` | Same question written informally, without accents or with typos. | 1 |
| `keyword-only` | A few keywords instead of a question (search-box style). | 1 |
| `long-noisy` | Long conversational question with irrelevant details around the real ask. | 1 |
| `boundary-value` | Amount exactly at a legal threshold ('superior a' means equal does not count). | 3 |
| `other-year` | Asks about another exercise/year; the 2026 rules must not be applied to it. | 5 |
| `future-year` | Asks about a future exercise with no official source yet; must abstain. | 2 |
| `calendar-vs-exercise` | Confuses the event year with the exercise (exercício 2026 = ano-calendário 2025). | 2 |
| `scope-boundary` | The user falls outside the rule's subject (e.g. non-residents). | 3 |
| `stale-source-conflict` | An official Q&A passage has an outdated figure; the IN value must win. | 3 |
| `false-premise` | The question assumes something false; the answer must correct it. | 3 |
| `multi-condition` | Several facts; the decisive rule must be retrieved, not a merely related one. | 1 |
| `below-threshold` | Amount below a threshold; the conclusion must stay limited to that criterion. | 2 |
| `arithmetic` | Needs simple arithmetic on the user's facts (e.g. 12 x a monthly amount). | 2 |
| `personalized-advice` | Asks for a personal tax calculation; explain rules, do not compute a final amount. | 2 |
| `out-of-scope-tax` | Another tax (ISS, ITCMD, MEI/Simples); must abstain. | 6 |
| `out-of-scope-jurisdiction` | Another country's tax; must abstain. | 2 |
| `off-domain` | Not about taxes at all; must abstain. | 2 |
| `prompt-injection` | Tries to override instructions or dictate the answer; must not comply. | 2 |
| `unsupported-language` | Not in Portuguese; the fixed Portuguese-only notice is expected. | 2 |
| `missing-source` | An IRPF topic absent from the corpus; must abstain rather than use model memory. | 2 |
| `insufficient-evidence` | Generation only: in-scope question whose fixed context does not answer it. | 2 |

```json
"edge_case": "stale-source-conflict"
```

### `style`

*string (category)* · retrieval: metadata

How the question is phrased relative to the official text.

**Accepts:** One of the values below.

| Value | Meaning | Cases |
| --- | --- | ---: |
| `source-wording` | Uses the official text's vocabulary (easiest for retrieval). | 27 |
| `paraphrase` | Same meaning in everyday wording. | 18 |
| `scenario` | Describes the user's situation; the legal question is implicit. | 24 |

```json
"style": "scenario"
```

### `covers`

*array of strings* · retrieval: metadata

Human-readable legal/Q&A references the case covers; drives the coverage report and lets labels be migrated if chunking changes.

**Accepts:** Free text such as 'IN art. 11, §3, I', 'P&R 007', 'Guia: limites'.

```json
"covers": ["IN art. 11, §3, I", "P&R 007"]
```

### `label_notes`

*string* · retrieval: metadata, generation: metadata, answer: metadata

Why these anchors and expectations were chosen, what was rejected and why, and dated label changes. The audit trail for reviewers.

**Accepts:** Free text.

```json
"label_notes": "ADDED Q007: its Atenção repeats the Art. 11 §3 list."
```

### `derived_from`

*string (case id)* · generation: metadata

The end-to-end case this generation case mirrors (same question and criteria), so retrieval and generation failures can be told apart.

**Accepts:** An answer-NNN id.

```json
"derived_from": "answer-033"
```

## Run results and metrics

### `strategy` (Run configuration)

How evidence was obtained for the run.

| Value | Meaning |
| --- | --- |
| `hybrid_rerank` | Production since V2: lexical+semantic candidates reordered by an LLM reranker. |
| `semantic` | Embedding similarity only (production in V0-V1). |
| `hybrid_rrf` | Unweighted reciprocal-rank fusion of lexical and semantic (diagnostic). |
| `lexical` | PostgreSQL full-text ranking (diagnostic; no API calls). |
| `lexical_authority` | Lexical with a bounded authority boost (diagnostic). |
| `fixed_context` | Generation suite: evidence comes from the case. |

```json
"strategy": "hybrid_rerank"
```

### `outcome (actual_outcome)` (Answer results)

What the answer pipeline returned for a case.

| Value | Meaning |
| --- | --- |
| `answered` | Claims with validated citations were shown. |
| `provider_abstained` | The model declined (deliberate). |
| `verification_abstained` | The answer verifier blocked the draft (deliberate system decision). |
| `unsupported_language` | Non-Portuguese question; fixed notice (deliberate). |
| `provider_rejected` | Validation rejected the draft (uncited chunk, figure not in evidence, malformed output). Safe for the user, but not counted as a deliberate abstention. |
| `no_retrieved_evidence` | Retrieval returned nothing. |

```json
"actual_outcome": "verification_abstained"
```

### `recall_at_one / three / five / ten` (Retrieval metrics)

Share of cases whose first acceptable anchor is within the top 1/3/5/10. recall@3 is the pass/fail metric; answers receive the top 5 (TAXRAG_ANSWER_TOP_K).

```json
"recall_at_three": 1.0
```

### `mrr_at_ten` (Retrieval metrics)

Mean reciprocal rank of the first acceptable anchor (1 = always first; 0 when outside the top 10).

```json
"mrr_at_ten": 0.986
```

### `preferred_recall_at_three` (Retrieval metrics)

Among cases with preferred anchors, share where a preferred passage is in the top 3. Diagnostic for source choice.

```json
"preferred_recall_at_three": 0.911
```

### `acceptable_rank / preferred_rank` (Retrieval results)

1-based rank of the first acceptable / preferred anchor in the top 10; null when absent.

```json
"acceptable_rank": 2
```

### `structural_pass_rate (passed)` (Answer metrics)

Automated check: answerable cases must answer and cite an acceptable anchor; abstention cases must abstain deliberately. Does not judge legal correctness; human review does.

```json
"structural_pass_rate": 0.879
```

### `abstention_passed / answerable_passed` (Answer metrics)

The pass count split by expected behaviour: declining correctly vs answering correctly.

```json
"abstention_passed": 10
```

### `unsafe_answers` (Answer metrics)

An answer was shown although the case requires abstention. The most harmful failure.

```json
"unsafe_answers": 1
```

### `validation_rejections` (Answer metrics)

Drafts blocked by deterministic validation (invalid citation, figure absent from evidence).

```json
"validation_rejections": 1
```

### `verification_abstentions / verifier_blocked_answerable` (Answer metrics)

Answers blocked by the second-pass verifier, and how many of those were answerable cases (its possible false positives; check each reason).

```json
"verifier_blocked_answerable": 1
```

### `answer_top_k / answer_verification / rerank_model / verifier_model` (Run configuration)

Answer-pipeline settings used by the run; comparisons warn when they differ.

```json
"answer_top_k": 5, "answer_verification": true
```

### `fixture_sha256 / source_versions.processing_version` (Run configuration)

Exact fixture content and corpus build (extractor + errata) behind the run; comparisons warn when they differ.

```json
"processing_version": "7+errata.3840d5c3"
```

### `retrieved_evidence` (Case results)

Chunks retrieved (or given, in generation) with rank, score and excerpt. Baselines keep excerpts only for ranks 1-3.

```json
{"anchor_key": "art-11-caput", "rank": 1, "score": 1.0}
```

### `cited_anchor_keys / cited_acceptable_anchor_keys` (Case results)

Anchors the answer cited, and those among them that are acceptable.

```json
"cited_acceptable_anchor_keys": ["art-11-caput"]
```

### `rejected_draft` (Case results)

The model's draft that validation or the verifier blocked (never shown to users). Read it to judge whether the block was right.

```json
"rejected_draft": {"claims": [{"text": "...", "citations": [...]}], "abstain": false}
```

### `validation_error` (Case results)

Why a draft was blocked before display (validation or verifier reason).

```json
"validation_error": "Claim 1 states figures absent from its cited evidence: R$ 81.000,00"
```
